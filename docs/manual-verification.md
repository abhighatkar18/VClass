# Manual verification and demo guide

Use an approved staging Firebase project, synthetic accounts, approved Cloudinary upload settings, and a restricted test Gemini key when needed. Record the branch, Android device or AVD API, date, and backend used. For each case, record the actual result and any failure evidence after execution. Rows marked **Pending** have no Phase 5 manual result.

| ID | Preconditions | Steps | Expected result | Actual / status | Notes |
|---|---|---|---|---|---|
| AUTH-01 | Staging Email/Password enabled. A fresh test email. | Open sign-up. Submit blank fields and an invalid email. Register with valid details. In the staging console, inspect the created user's profile document. | Invalid input stays on the form with readable feedback. A valid signup opens Home, and the initial profile contains a name and email with no password-derived fields. | — Pending | Record field names only. |
| AUTH-02 | A staging account and accessible test inbox. | Sign in with an incorrect password, then the correct password. Request a password reset from login. Complete the reset and sign in again. Force-stop, relaunch, then sign out and press Back. | Failed login shows an understandable error. Reset mail arrives. Relaunch restores the valid session. Back after sign-out cannot reopen protected data. | — Pending | Signed-out navigation and local validation also have automated tests. |
| CLASS-01 | Three synthetic accounts. | Create a class with one account. Join via its code with the other two. Try a second join with the same user. Promote one member and use the three accounts to check roster and archive actions. | Each member appears once. Teachers get permitted management actions. Students and outsiders cannot manage roles. Only the creator can archive. | — Pending | Keep the active fixture for assignment demos before archiving. |
| ASSIGN-01 | An active staging class and approved upload preset. | As a teacher or creator, make two same-title assignments. As a student, submit a different small file to each. View both lists as the author. Open an approved legacy fixture by its existing document ID, if available. | Each assignment shows its own submission and a working file link. The legacy record stays accessible at its original path. | — Pending | A merged list or a submission under the wrong ID is a failure. |
| FILE-01 | Staging Cloudinary and small test files. | Share a resource, tap its file link, then repeat an upload with the network unavailable. If the upload succeeded and only saving the link failed, select **Retry Save** after reconnecting. | Upload states are readable. The HTTPS file opens. Retry Save completes the reference without creating a second upload. | — Pending | Check the staging asset count if testing this failure path. |
| CAL-01 | An API 33+ test device and a future local date. | Create a valid event and save an announcement as another event. Open the marked calendar date. Run the reminder flow first with permission denied, then granted. Delete one future event before delivery. | Both events appear in the correct day, and a granted device receives one reminder for an eligible retained event. Deleted and denied events produce no alert. | — Pending | WorkManager delivery is subject to device scheduling. The current event UI supports add and delete. |
| AI-01 | A dedicated local Gemini test key and approved access. | Ask a study question and a follow-up. While waiting, type a draft. Disable networking before a subsequent question. Reconnect and try again. | The reply follows context. A pending send preserves the draft. Failures are readable and a later question can be sent. | — Pending | Use public sample prompts and exclude keys and personal data from screenshots. |
| PROFILE-01 | A signed-in staging user. | Edit details and select a small sample image. Reopen Profile. Try an invalid or unreadable image. | Valid details and photo persist. An invalid image shows actionable feedback. | — Pending | Confirm Android photo-picker behavior on a real device. |
| UI-01 | Small AVD, a tablet or larger device, and TalkBack. | Switch light and dark themes, increase font size, rotate, use the keyboard, visit all dashboard tabs, and navigate Back from classroom detail. Check TalkBack announcements on forms, tabs, calendar dates, and roster actions. | Controls remain reachable. Focus identifies actions and selection. Keyboard and system bars leave room for essential content. | — Pending | The README screenshots are existing emulator sign-up captures in both themes. |

For a short placement demo, run AUTH-02, CLASS-01, ASSIGN-01, and AI-01 with pre-created test data. Present the signed-out route and account role, then show how two same-title assignments remain separate. For screenshots, use the emulator's **Take screenshot** button with sample data, crop only if needed, and save verified captures under `docs/screenshots/`.
